# Audit — Known Bugs, Orphaned Code & PRD Divergences

## 1. Known Bugs

- ~~**ExifToolSession created per asset in commit loop** (`app.py:358`) — A new ExifToolSession is opened inside the `for idx, row in selected.iterrows()` loop, defeating `-stay_open` persistence. Each iteration opens and closes a subprocess, adding ~200ms overhead per asset.~~ _Fix: session created once before loop (`app.py:1052`), closed after. CLI uses thread-local sessions._
- ~~**`_preview_dry_run()` calls `log_event(None, ...)`** — When selecting 'D' from the interactive menu, `logger=None` causes `AttributeError: 'NoneType' object has no attribute 'info'`.~~ _Fix: removed log_event call from `_preview_dry_run()` — printed console output is sufficient._
- ~~**VISION_MODEL_PREFIXES included "qwen2" which matched non-vision models** (`engine.py:402`) — `qwen2` prefix matched `qwen2.5-coder` (code model), causing it to appear in the model dropdown.~~ _Fix: narrowed to `"qwen2.5vl"` and `"qwen2-vl"`._
- ~~**HW accel detection incomplete** (`engine.py:136`) — `detect_hw_accel()` only checks `cuda` (NVIDIA) and `qsv` (Intel), missing AMD AMF and macOS VideoToolbox.~~ _Fix: added `'amf'` to the detection list. macOS VideoToolbox remains missing (secondary platform, low priority)._
- ~~**Static images wrongly categorized as motion_graphics** — AI prompt lacked instruction to distinguish static images from video content.~~ _Fix: added CRITICAL OUTPUT RULES to `config.json` prompt instructing AI to never categorize static images as motion_graphics, glitch_vfx, timelapse, slow_motion, or cinemagraphs._
- ~~**AI storyboard grid description bleeds into output** — AI described the grid layout instead of content.~~ _Fix: changed `process_video_to_base64()` to extract a single midpoint frame instead of a 5×2 storyboard grid. No grid to describe — AI receives one representative frame per video._
- ~~**config.json prompts stored as arrays (list) instead of strings** — Temp updater script wrote 3 prompts (`general_broll`, `cinematography`, `motion_overlays`) as JSON arrays. `get_active_prompt().replace()` would crash with `AttributeError` on those profiles.~~ _Fix: joined array elements into single strings._
- ~~**Document categorization broken for non-PDF documents** — RTF categorised as `text_overlays`, MD as `presentation_slides`, PDF as `motion_graphics`. Root cause: prompt says "pick one category from the allowed list" but AI sees the global 48-category list, not the profile-specific `allowed_categories`.~~ _Fix: `get_active_prompt()` now appends explicit IMPORTANT constraint listing only profile-specific categories, and replaces "the allowed list" with the actual list in CATEGORY GUIDELINES section._
- ~~**`compute_asset_hash()` returns `None` for documents** (`engine.py:1604-1620`) — Only handles `VIDEO_EXTENSIONS` and `IMAGE_EXTENSIONS`. Documents are silently skipped by `find_duplicates()`.~~ _Fix: `compute_asset_hash()` now handles documents via `_compute_document_hash()`. Returns `sha256:{hash}` for binary docs, `sha256:{hash}` of extracted text for small text files. `find_duplicates()` groups by hash type (phash vs sha256), compares within groups only. 3 new tests added._
- ~~**FontBBox pdfminer warning clutters logs** — Known upstream pdfminer.six issue. Harmless warning from PDFs with incomplete font descriptors.~~ _Fix: `logging.getLogger("pdfminer").setLevel(logging.ERROR)` added at top of `extract_text_pdf()`._
- ~~**Metadata-only mode partially broken for documents** — PDF works via ExifTool but uses Windows EXIF fields. DOCX needs `python-docx` directly. TXT/MD/RTF have no standard metadata — writing silently fails.~~ _Fix: Layer 16.3 — per-format metadata strategy. DOCX via python-docx, XLSX via openpyxl, TXT/MD/RTF/CSV/PPTX skip gracefully. `skip_metadata` param added to `execute_commit()`._
- ~~**Bootstrap hardcodes `qwen2.5vl:7b`** — First-time user has no model comparison or selection.~~ _Fix: ModelSelectionDialog added to bootstrap.py with 4 model options (size/quality/radio). Downloads user-chosen model. `check_environment()` now returns `vision_models` list._
- ~~**Vision model detection false negative** — `VISION_MODEL_PREFIXES` missing `qwen2.5-vl` (hyphenated) and `qwen3-vl`. Ollama returns `qwen2.5-vl:7b` but prefix list only had `qwen2.5vl`. Sidebar showed model installed, but badge showed red "no vision model".~~ _Fix: added `qwen2.5-vl` and `qwen3-vl` to `VISION_MODEL_PREFIXES`._
- ~~**Undo/rollback not implemented** — No way to revert a commit batch. _Fix: `log_commit_batch()`, `rollback_last_batch()`, `list_undo_batches()` in engine.py. CLI `--rollback` flag. Analytics tab "Undo Last Commit" button. All 4 commit paths (batch, interactive accept/edit/bulk/custom) log undo records._
- ~~**`check_environment()` model detection inconsistent with sidebar** — `available_models()` handled `hasattr(m, 'model')` for ollama model objects, but `check_environment()` fell back to `str(m)` giving `<Model: qwen2.5-vl:7b>` which `_is_vision_model()` couldn't match. Sidebar showed model in dropdown but env badge showed red "no vision model" and upload was blocked.~~ _Fix: `check_environment()` now uses same 3-branch name extraction as `available_models()`._
- ~~**GPU decode failure aborts extraction with no CPU fallback** — `process_video_to_base64()` used `-hwaccel` when available, but a real decode failure (inactive GPU / unsupported codec) returned `None` and Phase 1 aborted with "Extraction failed".~~ _Fix: `_extract_frame_to_base64()` extracted as the low-level decoder; `process_video_to_base64()` retries with software decoding on HW failure and records the file in an optional `fallback_log`. `app.py` persists the names to `st.session_state.hw_fallback_files` and renders a durable `st.warning` ("GPU decoding failed … fell back to CPU") in the post-analysis status. Cleared on file change / Clear All / Reset App. 3 new unit tests in `tests/test_extraction.py`._
- ~~**One video staged as two duplicate assets** — `audio_transcription_cache` holds both standalone audio transcriptions AND video audio-track transcriptions. Phase 2 built one analysis item per cache entry, so a video produced 2 assets (frame + its transcription) and duplicate detection flagged them.~~ _Fix: `app.py` `_analysis_fragment()` filters `audio_items` to standalone audio files (`AUDIO_EXTENSIONS`); video transcriptions remain as prompt context for the frame analysis, and the redundant per-video AI call is eliminated._
- ~~**Document/audio analysis slow — vision model used for text-only prompts** — `analyze_document_with_ai()` and the audio-transcription fragment routed every prompt through the big vision model, wasting compute on documents/transcripts that carry no image.~~ _Fix: separate text model added. `engine.py` gains `TEXT_MODEL_NAME` (config `model.text_model`, default `qwen2.5:3b`); `OllamaProvider._analyze_prompt_only()` uses `self.text_model or self._model`. `app.py` sidebar gains a "Text model (documents & audio)" selector (non-vision models only, download button) that persists to config; `_analysis_fragment()` sets `prov.text_model` before `analyze_text`. 5 new tests in `tests/test_providers.py`._
- ~~**Onboarding 'Skip' still forced a full install** — A first-time user who clicked Skip in the questionnaire got `profile=[]` but the install pipeline (Ollama ~1.5 GB, then models) ran unconditionally, contradicting "skip launches the app".~~ _Fix: `bootstrap.main()` early-returns to `_launch_app(win)` when `do_installs` is False (empty profile). Env checks + the new in-app model download buttons cover the rest. Onboarding feature summary: profile-aware `check_environment(profile)`, `MODEL_CATALOG` + GPU-aware `recommended_models()`, registry-validated model tags (`validate_ollama_model`), `setup.json` persistence, `@st.fragment` download progress. 29 new tests in `tests/test_setup.py`._
- ~~**Choose-AI-model dialog cut off options with no way to scroll** — The 560×680, non-resizable dialog packed 7 model rows into a fixed body; on shorter screens the last rows and the Continue button fell below the fold and were unreachable.**_ Fix: the model list now lives in a scrollable `Canvas` panel with a scrollbar, mouse-wheel support, a pinned header/footer, and a resizable window whose height clamps to the screen. Every option and the Continue/Skip buttons are always reachable._
- ~~**Closing a wizard dialog could freeze the app** — The registry-check background thread called `self.top.after(0, ...)` from a non-main thread (Tk is not thread-safe) after the dialog was destroyed, and each dialog ran inside `wait_window()`'s nested event loop — destroying a grab-holding Toplevel there is the classic Windows tkinter hang.~~ _Fix: results are pushed to a `queue.Queue` and applied via a main-thread `after(200, ...)` poll that stops when the dialog closes; all three dialogs now close through `_close_dialog()` (`grab_release()` then `destroy()`), and `main()` runs dialogs through `_show_modal()`, a plain `update()` loop that is immune to the nested-loop destroy hang. Verified by a freeze-regression AppTest that closes the dialog mid-registry-check in <0.5s._
- ~~**Models reported "installed" while Ollama daemon down** — `OllamaProvider.available_models()` caught any `ollama.list()` failure and fell back to the catalog from `config.json`; `app.py` treated whatever it returned as the *installed* set, so every catalog model (Qwen VL, Llava, …) was labeled `(installed)` with its per-model Download button hidden even though nothing was installed. Reported in v1.6.0 first-run.~~ _Fix: `available_models()` returns `[]` on failure. The dropdown already appends `MODEL_CATALOG` alternatives, so the catalog is still browsable — now honestly marked `(not installed)` with working download buttons._
- ~~**Wizard use-case + plan dialogs had unreachable footer buttons on short screens** — `UseCaseDialog` (560×520) and `PlanConfirmDialog` (560×460) were fixed-size and packed their row lists into a non-scrolling body, so on smaller displays the footer (Continue / Skip, Start setup / Back) fell below the fold with no way to scroll — appearing as "no OK or cancel button".~~ _Fix: both dialogs are now resizable with a screen-clamped height, a scrollable `Canvas` body (mouse-wheel + scrollbar), pinned footers, and Enter/Escape bindings. Only the model dialog was covered by the earlier scroll fix (audit line 24)._
- ~~**No in-app path to install missing dependencies** — Closing the onboarding dialog (skip) launched the app with zero installs; env badges showed FFmpeg/ExifTool/Ollama missing but nothing offered to install them.~~ _Fix: the diagnostics panel now renders a "Setup incomplete — install missing components" CTA (`_spawn_setup_wizard()` → `bootstrap.py --setup`) when FFmpeg/ExifTool are missing, and an "Open setup wizard" button when the local runtime is down. Installers still run in the desktop wizard, which is the single source of truth for dependency installs._
- ~~**Streamlit Run/Deploy toolbar flashed on startup** — The packaged app injected CSS to strip Streamlit chrome only after first render, so the native toolbar appeared briefly before being hidden.~~ _Fix: `.streamlit/config.toml` sets `[client] toolbarMode = "minimal"` (validated against Streamlit 1.59.1), so the developer toolbar never renders._
- **llama.cpp runtime fallback added** — `LlamaCppProvider` (OpenAI-compatible, `http://localhost:8080/v1`, `LLAMACPP_BASE_URL` env/config override) registered as `llamacpp`; `check_environment()` detects `llamacpp_running` and, when Ollama is down, populates `vision_models`/`text_models` from the llama-server. Sidebar offers "Local (llama.cpp)" only when the server is reachable; `switch_ai_provider` skips API-key handling for it. **v1.6.2 upgrade:** the desktop wizard now *installs* the runtime for fresh installs — downloads `llama-server.exe` (~18 MB, `_llamacpp_runtime_urls()` with pinned-b10327 fallback), then a GGUF vision/text model from `LLAMACPP_GGUF_CATALOG` (7B Q4_K_M + mmproj Q8_0, 2B Q4_K_M + mmproj, or `qwen2.5:3b` text; HF download falls back to `hf-mirror.com`). Wires config via `configure_llamacpp_install()` and boots the daemon via `ensure_llamacpp_server()`. If Ollama is already installed, the wizard reuses it and does not ask for llama.cpp. Not yet validated against a real `llama-server` on hardware — strict `json_schema` `response_format` on llama.cpp is unverified (Ollama is the safe fallback).
- ~~**Bootstrap binary downloads had no checksum verification** (impl. plan 20.1) — FFmpeg, ExifTool, llama.cpp runtime, and GGUF models were fetched over HTTPS but nothing verified the bytes against a published digest.~~ _Fix (v1.6.3 security pass): `download_file()` now rejects non-HTTPS URLs and, when an `expected_sha256` is supplied, deletes the file and raises on mismatch. `sha256_file()`/`verify_sha256()` are the shared streaming helpers. Every downloader verifies against a published digest: FFmpeg from gyan.dev's `.sha256` file, ExifTool from `exiftool.org/checksums-<ver>.txt`, llama.cpp runtime from the GitHub API `digest` field + `LLAMACPP_RUNTIME_PINNED_DIGESTS` (b10327/b10326), and GGUF models from `LLAMACPP_GGUF_CATALOG` `sha256`/`mmproj_sha256` fields (captured from HF's LFS oids). A build with no published digest is skipped, never installed. 15 new tests._
- ~~**Cross-drive commits fail via `Path.rename`** — AGENTS.md mandates `shutil.move`, but `execute_commit` (metadata-only + batch) and `execute_commit_batch` used `Path.rename`, which raises WinError 17 when source and destination are on different drives.~~ _Fix (v1.6.3 remediation): `_commit_move()` helper uses `os.rename` with a copy+delete fallback for cross-drive / filesystem-dependent failures, and retries with a `_N` suffix on `FileExistsError`. Also dedups the `skip_rename` copy target, which previously could silently overwrite an existing same-name file. Shared by both commit paths._
- ~~**`reload_config()` only partially refreshed globals** — After a config save, `DEFAULT_TEMPLATE_STRING`, `PROMPT_PROFILES`, `CURRENT_PROVIDER`, `TEXT_MODEL_NAME`, `IMAGE_PREVIEW_MAX_EDGE`, `VIDEO_GRID_SCALE`, and `DOCUMENT_EXTENSIONS` were never refreshed, so the app kept using stale values until restart (e.g. a new text model or extension list didn't take effect).~~ _Fix: `reload_config()` now refreshes every config-backed module global, including a stray module-scope assignment that stringly ended up outside the function._
- ~~**Rollback dropped the undo-log entry on partial failure** — `rollback_last_batch()` rewrote `undo_log.jsonl` without the current batch even when `failed > 0`, so interrupted rollbacks couldn't be retried and the remaining files were stranded.~~ _Fix: the batch entry is only removed when the rollback fully succeeds (`failed == 0`); partial failures keep the batch so it can be retried._
- ~~**AI response parser accepted non-object JSON** — `_parse_ai_response()` returned `"null"`, bare strings, and arrays as "valid" data, which then crashed downstream when keys like `new_filename` were accessed.~~ _Fix: non-dict parses are rejected; `_parse_and_validate()` additionally requires `tags` to be a list when present._
- ~~**ExifTool batch errors silently discarded + IPC deadlock risk** — `execute_commit_batch` ignored the ExifTool output, so a file whose metadata write failed was reported as successfully committed; `execute()`/`execute_batch()` blocked indefinitely if the subprocess stalled (no timeout).~~ _Fix: `ExifToolSession` now drains stdout on a daemon reader thread into a queue; every read is bounded by a 60s timeout and raises on a dead process. `execute_batch()` sends one `-execute` per file and returns one output per arg-set; `execute_commit_batch`/`execute_commit` surface `ERROR:ExifTool metadata write failed for <file>` when ExifTool reports `Error:`._
- ~~**`check_ollama_health()` failed to detect vision models** — model list entries that came back as objects (instead of dicts) had `str(m)` applied, producing `<Model: qwen2.5-vl:7b>` which `_is_vision_model()` can't match; also flashed a false "disconnected" on the first transient failure.~~ _Fix: renamed to use the same 3-branch name extraction as `check_environment()` (`dict -> .get('name')`, `hasattr m.model`, else `str`), with one retry on transient failures._
- ~~**Keychain failures surfaced only as raw exceptions or were silently swallowed** (impl. plan 20.2) — `save_api_key`/`load_api_key` raised `RuntimeError` inside Streamlit callbacks where it was uncaught, and `load_api_key` at the API-key input could crash the sidebar.~~ _Fix (v1.6.3 remediation): new `keyring_available()` probe (`engine.py`) reports backend health without storing; `app.py` guards every keyring call site — a sidebar warning when the keychain is unavailable, an error caption when a stored key can't be read, `_on_api_key_change()` catches the save failure into `keyring_warning`, and the engine switch surfaces `switch_error`. `keyring_available` covered by 2 new tests._
- ~~**Streamlit bind address was implicit and Docker exposed all interfaces** (impl. plan 20.3) — the desktop EXE relied on Streamlit's implicit `localhost` bind (safe but undocumented, no LAN opt-in), and `docker-compose.yml` published `11434`/`8501` on all host interfaces; Ollama and the renamer UI have no authentication.~~ _Fix (v1.6.3 remediation): explicit `[server] address = "127.0.0.1"` in `.streamlit/config.toml`; `bootstrap.py` passes `--server.address=127.0.0.1` unless `config.server.lan_expose=true`; Config-tab "Expose on local network" toggle + warning; compose host ports bound to `127.0.0.1:` with an opt-in comment._
- ~~**CSV cells could carry spreadsheet formulas; session files were trusted** (impl. plan 20.4) — exported CSV cells starting `=`/`+`/`-`/`@` were interpreted as formulas by Excel/Sheets, and `load_session()` crashed or trusted arbitrary JSON (`staged_assets` entries could be non-dicts; symlinked paths were followed).~~ _Fix (v1.6.3 remediation): `_neutralize_csv_formula()` prefixes a `'` on both import and export (and tags individually on import); import clears `proposed_filename` values containing path separators; `load_session()` rejects non-object JSON, skips malformed asset entries, and never follows symlinks. `_safe_stem()` in `_commit_move()` strips `/`/`\`/`..`/`:` so a staged name can never traverse out of the target folder (commit-level lock-in test added)._
- ~~**Logs recorded absolute paths** (impl. plan 20.5) — JSONL entries for commits/errors carried absolute source/target paths, leaking the user's directory layout.~~ _Fix (v1.6.3 remediation): `config.logging.redact_paths` (default `true`) drives `_redact_paths_in_text()`, which masks Windows drive/UNC/POSIX absolute paths inside `log_event` records and nested details._
- **Clear All no longer deletes saved sessions** (v1.6.4 Wave 2) — intentionally diverges from the earlier "Clear All also deletes sessions" behavior; sessions now only go away via the explicit Delete button in the Session expander. User-approved scope. `audit.md` §3 reference updated.
- **Commit-success reset diverges from AGENTS.md contract by design** (v1.6.4 Wave 2) — after a commit, failed rows are kept for retry and unselected rows stay staged, so `uploaded_files`/`temp_dir`/`output_dir`/`logger` are intentionally NOT cleared. Documented inline at the commit block; full reset is Clear All. Matches REMEDIATION Wave 2 item (document divergence).
- **`DOCUMENT_EXTENSIONS` was a list, not a tuple** (Wave 3) — `load_config()` tuple-ized `video_extensions`/`image_extensions`/`audio_extensions` but left `document_extensions` as a list, so CLI's `valid_exts = VIDEO_EXTENSIONS + IMAGE_EXTENSIONS + AUDIO_EXTENSIONS + DOCUMENT_EXTENSIONS` crashed on every run with `TypeError: can only concatenate tuple (not "list") to tuple`. _Resolution (feat/auto-sort-folders): `load_config()` now tuple-izes `document_extensions` too, matching the other three extension families. Verified via CLI smoke test (concatenation no longer crashes)._
- **CLI `--import-csv` ignored `--non-interactive`** — the CSV import branch of `process_library` called `_run_staging_phase` without the `non_interactive` flag, so `-y` was silently dropped and interactive prompts (custom-category, execution path) still fired when running off an imported CSV. _Resolution (feat/auto-sort-folders): `non_interactive` now threaded into that call site, matching the apply-all branch._
- **Session-file timestamp collisions** (Wave 3) — two saves within the same second previously overwrote each other; `save_session()` now suffixes `_1`, `_2`, … on collision. Verified in `tests/test_session.py`.
- **Malformed session blocks could crash restores** (Wave 3) — `load_session()`/`list_sessions()` hardened: non-list `staged_assets` and non-dict `uploaded_files`/`settings` are coerced to empty, non-dict `created` falls back to the filename stem. `_valid_session_asset()` unchanged.
